# Dental Supply Storage

ระบบคลังวัสดุทันตกรรมด้วย Next.js App Router, TypeScript และ React ธีมสีม่วง

## เริ่มใช้งาน

```bash
npm install
npm run dev
```

เปิด http://localhost:3000

```bash
npm run build
npm start
```

## ความสามารถ

- ภาพรวมจำนวนวัสดุ มูลค่าสต็อก และการแจ้งเตือน
- ค้นหาด้วยชื่อ/รหัส กรองหมวดหมู่และสถานะ
- เพิ่มวัสดุ รับเข้า เบิกออก พร้อมประวัติ
- ป้องกันรหัสซ้ำ ยอดติดลบ และเบิกวัสดุหมดอายุ
- แจ้งเตือนสต็อกต่ำและหมดอายุภายใน 90 วัน
- ส่งออกข้อมูล JSON
- รองรับมือถือ และฟอร์มภาษาไทย

## การเก็บข้อมูล

รุ่นนี้เป็นต้นแบบสำหรับทดลองใช้งาน เริ่มต้นด้วยคลังว่าง เก็บข้อมูลด้วย localStorage บนเบราว์เซอร์แต่ละเครื่อง ไม่มีฐานข้อมูลกลาง ระบบล็อกอิน หรือการซิงก์หลายผู้ใช้ การล้างข้อมูลเบราว์เซอร์จะลบข้อมูลที่บันทึก ควรส่งออกข้อมูลสำรองก่อนล้างข้อมูล

วัสดุหนึ่งรายการมีวันหมดอายุเดียว ยังไม่แยกหลายล็อต การใช้งานจริงร่วมกันต้องเพิ่มฐานข้อมูล การจัดการล็อต การยืนยันตัวตน และสิทธิ์ผู้ใช้

## ฐานข้อมูล MySQL / MariaDB

ตั้งค่าใน `.env` ตาม `.env.example` โดยไฟล์ `.env` ไม่ถูกเก็บใน Git

- Host: `127.0.0.1`
- Port: `3307`
- Database: `dental_supply_storage`

ตรวจสอบการเชื่อมต่อ:

```bash
npm run db:check
```

ใช้ `getDb()` จาก `lib/db.ts` ใน Route Handlers หรือโค้ดฝั่งเซิร์ฟเวอร์เท่านั้น และใช้ parameterized queries (`execute` พร้อม placeholders) สำหรับข้อมูลที่ผู้ใช้กรอก

การเชื่อมต่อฐานข้อมูลถูกเตรียมแล้ว แต่หน้าคลังวัสดุยังใช้ localStorage ตามเดิม สร้างตารางแล้ว แต่ยังไม่ได้ย้ายการบันทึกวัสดุและประวัติของหน้าเว็บไปฐานข้อมูล

## ตารางฐานข้อมูล

Schema: `database/migrations/001_inventory.sql`

| Table | หน้าที่ |
| --- | --- |
| categories | หมวดหมู่วัสดุ |
| units | หน่วยนับ |
| storage_locations | ตำแหน่งจัดเก็บ |
| materials | รหัส ชื่อ สต็อกขั้นต่ำ ยอดคงเหลือ ราคา และวันหมดอายุ |
| inventory_documents | เอกสารรับเข้า/เบิกออก ผู้ทำรายการและหมายเหตุ |
| inventory_movements | รายการวัสดุในเอกสาร จำนวน และยอดหลังทำรายการ |
| schema_migrations | รุ่นโครงสร้างฐานข้อมูลที่ติดตั้งแล้ว |

ตารางวัสดุและประวัติเริ่มต้นว่าง มีข้อมูลตั้งต้นเฉพาะหมวดหมู่ 4 รายการและหน่วยนับ 5 รายการ การแจ้งเตือนคำนวณจาก `stock <= minimum_stock` และ `expiry_date` ส่วนมูลค่าคลังคำนวณจาก `SUM(stock * unit_price)`

เมื่อเชื่อม API รับเข้า/เบิกออก ต้องทำ transaction โดยล็อกแถววัสดุด้วย `SELECT ... FOR UPDATE` ตรวจวันหมดอายุและยอดคงเหลือ อัปเดต `materials.stock` และเพิ่มเอกสารพร้อมรายการเคลื่อนไหวก่อน commit เพื่อป้องกันยอดคลาดเคลื่อนเมื่อมีหลายผู้ใช้ Schema ไม่ได้อัปเดตยอด stock อัตโนมัติจากการ insert movement

## สำรองและกู้คืน

```bash
npm run db:migrate
npm run db:backup
node scripts/verify-backup.mjs
```

- `db:migrate` สำรองก่อนสร้าง schema และสำรองอีกครั้งหลังสร้าง ไม่ล้างตารางเดิม และรันซ้ำได้เมื่อ migration สำเร็จแล้ว
- `db:backup` เก็บ SQL พร้อม manifest จำนวนแถวและ SHA-256 ใน `backups/` ซึ่งถูกยกเว้นจาก Git
- หยุดการเปลี่ยน schema ระหว่าง backup ข้อมูล InnoDB ถูกอ่านด้วย consistent snapshot
- เครื่องมือสำรองนี้รองรับ base tables แบบ InnoDB หากเพิ่ม views/triggers/routines/events จะหยุดและให้ใช้ mysqldump
- `verify-backup.mjs` ตรวจไฟล์ after-schema ล่าสุด โดยกู้คืนในฐานข้อมูลชั่วคราว ตรวจ schema/จำนวนแถว/ข้อจำกัดสต็อก แล้วลบเฉพาะฐานข้อมูลทดสอบที่เพิ่งสร้าง
- กู้คืน SQL ลงฐานข้อมูลว่างที่สร้างแยก ผ่าน MySQL client หรือเครื่องมือฐานข้อมูล โดยเลือก database เป้าหมายก่อนรันไฟล์ ไฟล์ไม่มีคำสั่ง DROP TABLE หรือ DROP DATABASE
- ไฟล์สำรองอยู่ในเครื่องนี้ ยังไม่ได้คัดลอกไปอุปกรณ์อื่นหรือกำหนดสำรองอัตโนมัติ
